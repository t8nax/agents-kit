# Навык: retool

Меняется механизм: файлы этого репозитория. Что менять нельзя и почему — в `CLAUDE.md`, он у сессии уже в контексте. Здесь — порядок работы.

## Куда кладётся правка

| Файл | На что отвечает |
|---|---|
| `hooks/hooks.json` | когда кит вмешивается в сессию |
| `scripts/link-state.ps1` | как связаны копия и база |
| `scripts/session-start.ps1` | что видит сессия на старте |
| `scripts/link.ps1` | как связывают копию с базой и как показывают связь |
| `scripts/base-init.ps1` | с чего начинается новая база |
| `scripts/check-kit.ps1` | чем кит проверяется |
| `reference/invariants.md` | перечень того, что действует в каждой сессии под китом, — без причин |
| `reference/base-layout.md` | как ведут файлы базы |
| `skills/<имя>/SKILL.md` | как идёт работа контура проекта под китом |
| `.claude/skills/<имя>/SKILL.md` | как идёт работа над самим китом |
| `template/base/` | каркас новой базы |
| `README.md` | как кит ставится и с чем связывается |
| `CLAUDE.md` | что в ките менять нельзя и почему |
| `.claude-plugin/plugin.json` | чем кит объявлен |

**Два файла меняются по существу — значит, замысла два.** Разнести и вести по очереди. Запись о правке — строка в таблице выше, строка в раскладке базы, проверка в сверке — частью того же захода, а не вторым замыслом.

## Когда заводится новый файл

Изменение не ложится ни на одну строку таблицы — у него своя ответственность, и ему нужен свой файл. Ложится — правка идёт в существующий. Где что лежит:

- **скилл для проектов под китом** — `skills/<имя>/SKILL.md`; в `plugin.json` не регистрируется, подхватывается по соглашению каталогов;
- **скилл для работы над китом** — `.claude/skills/<имя>/SKILL.md`; в проекты он не едет;
- **скрипт** — `scripts/<имя>.ps1`;
- **справка** — `reference/<имя>.md`;
- **файл шаблона базы** — `template/base/`; строка о нём дописывается в `reference/base-layout.md`.

## Референсы

`D:\Projects\tfb-agents-kit` и `D:\Projects\tfb-kit-share` — прежние киты. Их читают и не правят.

Готовое решение оттуда берут, когда оно ложится на текущий кит. Раскладку и имена файлов не переносят: там она другая. Что не ложится, придумывают заново.

## Порядок

1. Назвать изменение одной фразой и найти ему адрес: файл из таблицы или новый по правилам выше.
2. Прочитать файл целиком до правки.
3. Править по месту.
4. Правка задевает подачу хука, состояние связи или заведение базы — проверка в `check-kit.ps1` дописывается тем же заходом.
5. `pwsh -NoProfile -File scripts\check-kit.ps1` — зелёный.
6. Свести текст кита — ниже.
7. Коммит явными путями.

## Свести текст кита

Правка одного файла оставляет в соседнем прежнюю редакцию того же утверждения. Ни `check-kit.ps1`, ни глаз того, кто только что писал, этого не ловят, поэтому сверку делает субагент `Explore` — он читает и только читает.

В задании ему: что менялось в этой сессии, и требование прочесть весь текст кита — `README.md`, `CLAUDE.md`, `reference/`, `skills/`, `.claude/skills/`, `template/`, а в `scripts/*.ps1` шапки, комментарии и строки, которые скрипт печатает человеку. Сверяется текст, не код.

Возвращает пары: два адреса, утверждение, разошлись они по существу или нет. Ссылка строкой на другой файл и совпадение терминов — не находка.

Дальше правит основной агент:

- **пара совпадает** — оставить один адрес, второй заменить ссылкой или убрать;
- **пара разошлась по существу** — остановиться и спросить человека, какая редакция верна.

## Чего не делать

- Не заводить файл без своей ответственности и не класть скилл самого кита в `skills/`.
- Не копировать из референсов раскладку и имена файлов.
- Не отмечать правку сделанной, не прогнав обе сверки.
- Не поручать правку находок субагенту и не решать расхождение за человека.
