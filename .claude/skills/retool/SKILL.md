# Навык: retool

Меняется механизм — файлы этого репозитория. Что менять нельзя и почему — `CLAUDE.md`, он уже в контексте. Здесь — порядок работы.

## Куда кладётся правка

| Файл | На что отвечает |
|---|---|
| `hooks/hooks.json` | когда кит вмешивается в сессию |
| `scripts/link-state.ps1` | как связаны копия и база |
| `scripts/session-start.ps1` | что видит сессия на старте |
| `scripts/link.ps1` | как связывают копию с базой и как показывают связь |
| `scripts/base-init.ps1` | с чего начинается новая база |
| `scripts/base-check.ps1` | что в базе не так |
| `scripts/commit-gate.ps1` | пускать ли коммит в базу |
| `scripts/await-answer.ps1` | пришёл ли ответ оператора в память копии |
| `scripts/worktree-add.ps1` | как заводят рабочую копию рядом с основной |
| `scripts/check-kit.ps1` | чем кит проверяется |
| `reference/invariants.md` | что действует в каждой сессии под китом — без причин |
| `reference/base-layout.md` | как ведут файлы базы |
| `reference/task-memory.md` | как ведут память задачи и вопрос оператору в ней |
| `reference/backlog-record.md` | как пишут, нумеруют и берут запись бэклога |
| `skills/<имя>/SKILL.md` | как идёт работа контура проекта под китом |
| `.claude/skills/<имя>/SKILL.md` | как идёт работа над самим китом |
| `template/base/` | каркас новой базы |
| `README.md` | первое знакомство с китом: что это, как поставить, как начать |
| `CLAUDE.md` | что в ките менять нельзя и почему |
| `.claude-plugin/plugin.json` | чем кит объявлен |

**Два файла меняются по существу — значит, замысла два:** разнести и вести по очереди. Строка в таблице выше, строка в раскладке, проверка в `check-kit.ps1` — часть того же захода.

## Когда заводится новый файл

Изменение не ложится ни на одну строку таблицы — у него своя ответственность и свой файл; ложится — правка идёт в существующий.

- **скилл проектов** — `skills/<имя>/SKILL.md`, подхватывается по соглашению каталогов, в `plugin.json` не регистрируется;
- **скилл работы над китом** — `.claude/skills/<имя>/SKILL.md`, в проекты не едет;
- **скрипт** — `scripts/<имя>.ps1`; **справка** — `reference/<имя>.md`;
- **файл шаблона базы** — `template/base/` и строка в `reference/base-layout.md`. В подачу хука он сам не попадает: это правка списка подаваемых в `base-check.ps1`.

Готовое из прежних китов берут, когда оно ложится на этот; их раскладку и имена файлов не переносят.

## Порядок

**Правка идёт в основной ветке.** Кит грузится из рабочего дерева клона: какая ветка выложена, тот механизм и действует на всех проектах, а ветка под замысел выдала бы недоделанный кит за рабочий.

1. Назвать изменение одной фразой и найти ему адрес.
2. Прочитать файл целиком до правки и править по месту.
3. Правка задевает подачу хука, состояние связи, заведение базы, гейт коммита или ожидание ответа — тем же заходом проверка в `check-kit.ps1`. Исключение — правила сверки в `base-check.ps1`, почему — `CLAUDE.md`.
4. `pwsh -NoProfile -File scripts\check-kit.ps1` — зелёный.
5. Свести текст кита — ниже.
6. Коммит явными путями.
7. Пуш основной ветки в `origin` — один раз, когда закрыты все замыслы захода.

**Пуш забывается легче всего:** локально он ничего не меняет и нигде не краснеет, а кит ставят из репозитория.

## Свести текст кита

Правка одного файла оставляет в соседнем прежнюю редакцию того же утверждения, и ни `check-kit.ps1`, ни глаз пишущего этого не ловят. Поэтому сверку делает субагент `Explore`, только читающий.

Задание ему: что менялось в сессии и прочесть весь текст кита — `README.md`, `CLAUDE.md`, `reference/`, `skills/`, `.claude/skills/`, `template/`, а в `scripts/*.ps1` шапки, комментарии и строки, которые скрипт печатает. Сверяется текст, не код. Вернуть пары: два адреса, утверждение, разошлись ли по существу. Ссылка на другой файл и совпадение терминов — не находка.

Правит основной агент:

- **пара совпадает** — оставить один адрес, второй заменить ссылкой или убрать;
- **пара разошлась по существу** — спросить человека, какая редакция верна; не решать за него.

## Чего не делать

- Не заводить файл без своей ответственности и не класть скилл самого кита в `skills/`.
- Не отмечать правку сделанной, не прогнав обе сверки.
