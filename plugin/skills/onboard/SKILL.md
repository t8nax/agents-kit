# Навык: onboard

Довести каталог от «ничего нет» до связанной копии с непустой базой и местом оператора. Дальше — `flow` и `drive`, и каркас проекта уже задача `drive` со своим критерием.

Скрипты и раскладка кита: `..\..\scripts\` и `..\..\reference\base-layout.md` от каталога этого скилла.

## 1. Где мы сейчас

**Каталог не под git** — `git init`.

**Каталог под git** — `link.ps1 -Path <копия>` без `-Base`, прочитать отчёт:

- `связь двусторонняя` — кит уже стоит: сказать и отправить в `drive`;
- `на этой машине не назван`, `личного репозитория на этой машине нет` — связь есть, а места оператора на машине нет: раздел «Место оператора», разговор и шаг 3 не идут;
- `указатель разорван`, `это не база кита`, `связь односторонняя` — это разрыв, а не онбординг: показать отчёт и остановиться; чинит оператор;
- `не закончено сведение с remote` — показать отчёт и сделать, что в нём сказано;
- `формат не тот` — кит уже стоит, а базу надо перевести или обновить кит: показать отчёт. Перевод — сначала забрать базу, `sync.ps1 -Path <копия> -Repo Base -Action Pull`: её могли перевести с другой машины, и тогда отчёт `link.ps1` сменится. Вывод говорит «не забрано» или «недоступен» — перевод не запускать, а показать вывод оператору. Иначе спросить оператора, переводить ли базу сейчас, и тем же вопросом — его имя в базе по разделу «Место оператора»; согласен — команда из отчёта с этим именем, её вывод показать оператору, затем отдать базу — `-Action Push`;
- указателя нет — дальше.

**Каталог не корень репозитория** — спросить оператора, брать под кит репозиторий целиком или только этот каталог; при ответе «каталог» `link.ps1` зовётся с `-Scope Directory`.

**У проекта уже есть база** — склонирована с другой машины или ведётся для другой копии: спросить оператора, есть ли она и где. Есть — `link.ps1 -Base <база>`, затем снова `link.ps1 -Path <копия>` и по его отчёту, как выше; разговор и шаг 3 не идут. Связь поднята — сказать, что знание приедет со следующей сессии.

## 2. Разговор

Раскладка базы читается **до** разговора, вопросы — по ней.

**Спрашивается то, чего в репозитории нет.** Пустая папка — всё. Есть код — сначала прочитать его и спросить остаток; выводимое из кода в базу не идёт.

Не больше трёх вопросов блоком, каждый с черновиком ответа. Ответа нет — строки нет.

Среди вопросов — ведёт ли проект задачи в трекере. Ответ в базу не пишется: `tracker.md` заводит `tracker`.

## 3. Завести базу и связать

База лежит рядом с корнем репозитория и вне его. Предложить путь `<родитель корня репозитория>\<имя папки>-knowledge` и тем же вопросом — имя проекта, как его зовёт команда, с черновиком из имени папки (`order-service` → `Order Service`), и буквы, которыми проект нумерует бэклог, с черновиком из имени проекта (`Order Service` → `ORD`); какие буквы годятся — `..\..\reference\backlog-record.md`. Следом — вопросы раздела «Место оператора».

1. `base-init.ps1 -Path <база> -Operator <имя> -Name "<имя проекта>" -Prefix <буквы>`, а есть remote — с `-Remote <адрес>`: каркас и репозиторий базы, папка оператора и личный репозиторий.
2. `link.ps1 -Base <база>`, а под кит берётся каталог — `link.ps1 -Base <база> -Scope Directory`; обе стороны связи пишет он, список копий руками не правится.

## 4. Записать и закоммитить

Ответы разложить по раскладке через тест входа; решения — по файлу `decisions/` на область, со строкой `когда:`. Флоу не пишется: его пишет `flow`. Коммит базы явными путями, без кода, и отдать базу — `sync.ps1 -Path <копия> -Repo Base -Action Push`; что делать по выводу — раздел «Когда параллельные задачи сходятся» раскладки.

## 5. Передать работу

Сказать: связь поднята, база заполнена вот этим. Знание приедет **со следующей сессии** — хук отработал, когда копия ещё не была связана. Следующей сессией — `tracker`, если трекер у проекта есть, и `flow`: без сценария `drive` работу не начнёт. Потом первая задача — `drive`.

## Место оператора

Сюда ведёт отчёт `link.ps1` на шаге 1. У новой базы эти вопросы задаются на шаге 3, и `base-init.ps1` зовётся там один раз.

Имя оператора и личный репозиторий — по разделу «Оператор» `base-layout.md`, одним блоком вопросов:

1. Имя в базе — с черновиком из `git config user.name`. Перед вопросом прочитать `people/` базы: папка с этим именем есть — спросить, его ли она.
2. Есть ли у личного репозитория приватный remote и его адрес.

Затем `base-init.ps1 -Path <база> -Operator <имя>`, а есть remote — с `-Remote <адрес>`. Новую папку оператора он коммитит в базу сам.

Копия уже связана с базой — сюда ведёт шаг 1 — база сводится с remote: до чтения `people/` забрать её — `sync.ps1 -Path <копия> -Repo Base -Action Pull`, после `base-init.ps1` отдать — с `-Action Push`. Что делать по выводу `sync.ps1` — раздел «Когда параллельные задачи сходятся» раскладки.

## Чего не делать

- Не чинить разорванную связь и не заводить вторую базу вместо ремонта.
- Не выбирать имя оператора за него и не брать чужую папку в `people/` без его слова.
- Не разворачивать каркас проекта и не коммитить код.
