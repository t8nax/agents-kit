# Инварианты agents-kit

Модель: **агент делает инженерную работу, оператор — только то, чего агент не может**: принимает необратимое решение, даёт доступ, пишет коллеге.

## Три слоя, которые не смешиваются

| Слой | Где живёт | Кто правит |
|---|---|---|
| механизм | клон кита | только сессия, открытая в самом ките |
| знание проекта | отдельный репозиторий базы знаний, вне кода | рабочая сессия и оператор |
| код | рабочая копия проекта | команда проекта |

## Действует всегда

- **В репозиторий проекта знание не пишется, и каталог знания в нём не создаётся.** `CLAUDE.md`, `AGENTS.md`, `.claude/`, `.agents/` и `.codex/` в нём принадлежат проекту; субагентов оператора из его личного репозитория кладёт в рабочую копию только `agents-deploy.ps1` — мимо git проекта и не трогая отслеживаемые им файлы, а сессия туда не пишет.
- **Кит не правится из рабочей сессии другого проекта** — ни клон, ни установленная копия. Задача требует правки кита — это вопрос оператору, а работа идёт тем китом, что есть.
- **Ничего не пишется молча.** Файл базы меняет только явная правка, и агент говорит, что записал. Свободный разговор не фиксирует ничего.
- **Задачу в трекере сессия заводит и меняет только по слову оператора** — сказанному или записанному в его флоу — или как велит `tracker.md` базы.
- **Задача живёт файлом памяти своей рабочей копии:** есть файл — задача в работе, нет — не в работе. Другой пометки занятости кит не ставит, кроме назначения задачи трекера при её взятии; памяти чужой копии сессия не касается.
- **Одна рабочая копия — одна задача за раз.** Вторая параллельная — в новом `git worktree`.
- **Пока памяти нет, по задаче не делается ничего, кроме самого взятия:** ни этап сценария, ни правка кода.
- **Что нужно от оператора — вопрос в разделе «Оператору» памяти задачи, ответ — его строка `ответ:`.** Пока память заведена, оператор спрашивается только так — не инструментом вопроса и не репликой с ожиданием ответа; кроме остановки работы со знанием — её вопрос задаётся в разговоре. Ответ пишет оператор; сессия его не сочиняет. Сессия, у которой вся работа ждёт ответа, не засыпает, а ждёт свой файл; сессия не в Claude Code останавливается сводкой, и будит её оператор.
- **Рамку задачи держит то, как её поставили, и выходы пройденных этапов.** За рамку молча не выходят: понадобилось больше — вопрос оператору. Сужает задачу только оператор: несделанное из постановки доделывается, а не уезжает в бэклог.
- **Задача закрывается пройденным сценарием, а не мержем ветки.**
- **Флоу правит только `flow` по слову оператора и только свой — в личном репозитории.** `drive` флоу не правит: молчит или неоднозначен флоу — вопрос оператору.
- **Работа идёт по сценарию задачи, выбранному при взятии, и на другой сценарий задача не переходит:** этап без записанного выхода не пройден, без своего условия не пропускается, назад работа идёт только возвратом, записанным в сценарии; в базу пишет оркестратор, а не субагент. Этап против инварианта — вопрос оператору.
- **Задача идёт по флоу задачи, скопированному в её память при взятии, а не по `flow/`:** правка флоу касается задач, взятых после неё.
- **Прогресс не имитируется:** шаг закрывает проверка, а не намерение; отпавший шаг — названная причина.
- **Замеченное в правке этой задачи доводится в ней.** Замеченное в прежнем коде и не нужное задаче записывается в `backlog.md` личного репозитория сразу и без решения оператора попутно не делается; запись в работу выбирает оператор, если флоу не задал иного.
- **Решения проекта читаются до первого этапа сценария** — по поданному оглавлению `decisions/`, те, которых задача касается. Неизвестное решение не отменяется тем, что его не прочли.
- **Знание фиксируется в конце работы:** то, что дорого переоткрывать, — решение с причиной, понятое про продукт, сдвинутая граница. Память задачи — не знание.
- **Правила читаются до первой записи:** в базу — `base-layout.md`, во флоу — `flow-stages.md`, в память задачи — `task-memory.md`, в бэклог — `backlog-record.md`. Пути поданы в начале сессии.
- **Коммит в базу и в личный репозиторий — явными путями, а путь репозитория — в самой команде:** `git -C <репозиторий> commit -m "…" -- <пути>`, а не из каталога, заданного агенту отдельно; новый файл — точечным `git add`, удаляемый — `git rm`. Никогда `git add -A`, `git add .`, `checkout`, `stash`, `reset` в них; `pull`, `push`, `rebase`, `merge` — только через `sync.ps1`. Код коммитится в рабочую копию, знание — в базу, рамки агента, флоу, субагенты, бэклог и память задачи с её флоу — в личный репозиторий.
- **Секреты не попадают в git базы** — ни токены, ни строки подключения, ни локальный пароль, «заведомо непригодный» вне этой машины. Не попадают и в личный репозиторий. В коммит идёт политика; значение живёт там, где его читает код, а в базе — только в `local/` вне git и вне `local/me/`.
- **Язык базы знаний — русский.** Язык кода, тестов и коммитов задаёт проект.
