# Инварианты agents-kit

Модель: **агент делает инженерную работу, человек — оператор** — тот делает только то, чего агент не может: принимает необратимое решение, даёт доступ, пишет коллеге.

## Три слоя, которые не смешиваются

| Слой | Где живёт | Кто правит |
|---|---|---|
| механизм: сам кит — хуки, скиллы, персоны, проверки | клон кита | только сессия, открытая в самом ките |
| знание проекта | отдельный репозиторий базы знаний, вне кода | рабочая сессия и оператор |
| код | рабочая копия проекта | команда проекта |

## Действует всегда

- **В рабочий репозиторий знание не пишется, и каталог знания внутри него не создаётся никогда.** `CLAUDE.md`, `.claude/agents/` и `.claude/skills/` рабочего репозитория принадлежат проекту, кит их только использует.
- **Механизм не правится из рабочей сессии** — ни клон кита, ни его установленная копия. Кажется, что задача проекта требует правки кита, — это вопрос оператору, а работа продолжается тем китом, который есть.
- **Ничего не пишется молча.** Файл базы правится только явным шагом, и агент говорит, что именно записал. Свободный разговор не фиксирует ничего.
- **Задача живёт файлом рабочей памяти в базе:** есть файл своей ветки — задача в работе, нет — не в работе. Второй пометки о занятости не существует, и памяти чужой ветки сессия не касается.
- **Критерий закрытия записывается до работы,** и выйти за него молча нельзя: понадобилось больше — это вопрос человеку, а не решение на месте.
- **Прогресс не имитируется:** шаг закрывает проверка, а не намерение. Не прогнанный тест и не сделанный шаг в памяти отмечены быть не могут.
- **Знание фиксируется в конце работы, а не по ходу.** Записывается то, что дорого переоткрывать: действующее решение вместе с причиной, понятое про продукт, сдвинутая граница. Что именно проходит в базу, а что нет, — тест входа в раскладке.
- **Раскладка базы читается до первой записи в неё.** Правила ведения её файлов живут в `base-layout.md` кита, путь подан в начале сессии.
- **Коммит знания — явными путями:** `git commit -m "…" -- <пути>`, новый файл сначала точечным `git add` только его. Никогда `git add -A`, `git add .`, `checkout`, `stash`, `reset` в базе. Коммит кода уходит в рабочую копию, коммит знания — в базу.
- **Секреты в базу не попадают** — ни значений токенов, ни строк подключения, ни пароля стенда, «заведомо непригодного» вне этой машины. В базе живёт политика, значение живёт там, где его читает код.
- **Язык базы знаний — русский.** Язык кода, тестов и коммитов задаёт проект.
