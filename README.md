# agents-kit

Агентский кит для Claude Code: **агент делает инженерную работу, человек — оператор**.

Знание проекта — что за система, где граница решений агента, какие решения на нём действуют — живёт **отдельным репозиторием базы знаний**, вне кода и вне кита. Сессия находит базу сама, по указателю в git config рабочей копии, и получает её знание вместе с инвариантами кита в первую же секунду.

## Как связаны рабочая копия и база

Связь двусторонняя, и обе стороны обязательны.

| Сторона | Где лежит | Что говорит |
|---|---|---|
| указатель | `agents-kit.base` в локальном git config копии | где база этого репозитория |
| встречная запись | `agents-kit.json` в корне базы | какие рабочие копии база числит своими |

Почему сторон две, почему указатель лежит именно в git config и какие варианты отброшены — в [CLAUDE.md](CLAUDE.md).

## Установка

**Каталог автозагрузки — для того, кто кит правит.** Ссылка на клон кладётся в `~/.claude/skills/`, и кит загружается прямо из клона: правка действует со следующей сессии, переустанавливать нечего.

```powershell
New-Item -ItemType Junction -Path "$env:USERPROFILE\.claude\skills\agents-kit" -Target <клон кита>
```

**Маркетплейс — для того, кто китом только пользуется.**

```powershell
claude plugin marketplace add <клон или github-репозиторий>
claude plugin install agents-kit@agents-kit
```

**Важно:** при этом способе плагин **копируется** в `~/.claude/plugins/cache/…/<версия>/`, а `claude plugin update` сверяет только номер версии. Правка в клоне без поднятия версии в `plugin.json` до установленной копии не доедет, и ошибка эта тихая — сессия продолжает работать по старой версии. Поэтому кит правится при установке через каталог автозагрузки, а маркетплейс обновляется поднятием версии.

Оба способа одновременно включать нельзя: два экземпляра одного хука подадут контекст дважды.

## Связать проект с базой

Сначала заводится сама база — каталог рядом с рабочими копиями, вне рабочей копии, с именем вида `<проект>-knowledge`:

```powershell
pwsh -NoProfile -File <клон кита>\scripts\base-init.ps1 -Path <каталог базы>
```

Скрипт раскладывает каркас и заводит репозиторий базы; повторный прогон безопасен и заполненного не трогает. Что за файлы и по каким правилам в них пишут — [reference/base-layout.md](reference/base-layout.md).

Дальше из рабочей копии:

```powershell
pwsh -NoProfile -File <клон кита>\scripts\link.ps1 -Base <каталог базы>
```

Команда пишет обе стороны сразу. Вторая рабочая копия того же проекта связывается той же командой и попадает в тот же список. `git worktree` связывать не нужно: он приводится к копии, от которой заведён.

Без аргументов тот же скрипт показывает, как связано сейчас, и годится как первая диагностика, когда сессия говорит о разрыве.

## Что видит сессия

Открытая в связанной копии — **знание проекта целиком**: файлы базы содержимым, а не путём до них. Вместе с ними приходят путь базы, путь копии, текст [reference/invariants.md](reference/invariants.md) и путь [reference/base-layout.md](reference/base-layout.md) — правила ведения базы нужны только той сессии, что в неё пишет.

Открытая в репозитории без указателя или вне git — ничего. Стороны не сошлись — вместо этого сессия получает, что именно разорвано и что чинить, и останавливает работу со знанием.
